# stock-track

交易提醒：每天告訴你下一個交易日要對哪些股票進出場、是哪個策略觸發的。

- 網站／App：https://ed123698745ed-oss.github.io/stock-track/
- 資料：Supabase；抓取與推播：GitHub Actions（`.github/workflows/`）

## 安裝成 App（手機、電腦都可以）

- **iPhone**：用 Safari 開網站 → 分享 → 「加入主畫面」
- **Android**：用 Chrome 開網站 → 右上選單 → 「安裝應用程式」
- **電腦**：用 Chrome／Edge 開網站 → 網址列右側的「安裝」圖示

裝好後是獨立視窗、有自己的圖示。App 的儲存空間和瀏覽器分開，第一次開要重新貼一次 key、登入一次。

## 每日推播（`每日訊號推播` workflow）

週一到週五台北 19:30 主推播「明天要做的事」；21:07、22:37 補推（只推晚到的新訊號，沒有就不推）。

第一次設定：

1. Supabase → SQL Editor，貼上 `sql/001_strategy_actions.sql` 執行一次（重複執行沒關係）。
2. 這個 repo 的 Settings → Secrets and variables → Actions，新增
   `LINE_CHANNEL_ACCESS_TOKEN`、`LINE_USER_ID`（和 panhou-zhushou 用的同一組）。
3. Actions → 每日訊號推播 → Run workflow，`dry_run` 填 `1` 先看訊息內容，沒問題再填 `0` 實際推一次。

## 策略績效（`config/perf.json`）

網站「策略一覽」、交易卡的四指標（平均報酬／持有／單利年化／凱利）和 LINE 推播都讀這一份，數字來自 Drive 的「可執行策略總表」。

- 總表更新後：下載成 xlsx，跑 `python3 scripts/build_perf.py 可執行策略總表.xlsx`，提交 `config/perf.json`。
- 只搬數字不補算；空白／N/A 顯示「未提供」或「無虧損樣本」。唯一換算是半凱利＝凱利÷2。
- 回測 n<30 標「⚠ 小樣本」。持有天數有交易日、日曆日兩種，照總表標示單位。
- 情境用 `strategy_actions.variant` 對應（A09 七組、A10 兩季、009 五檔、014 兩種持有天數、015 三組）。

## 網站目標交易日

台北時間交易日 13:30 前顯示當天，之後切到下一個交易日（跳過休市日）。LINE 連結帶 `?d=日期`，點開即該則通知的日期；日期已過會標成歷史。過期提醒收進「日期已過」，不需要每天勾選，也不推定成交。

## 日曆型策略（`scripts/calendar_signals.py`）

只靠交易日曆就能算出日期的策略：A01 開紅盤、A09 上中下旬（7 組）、A10 航空股（2 組）、
009 產業旺季（5 檔）、021 台積電法說會前後。

- 交易日 = 平日且不在 `holidays` 表；某年的休市日還沒公布，那一年的訊號就不產生。
- 021 的法說日每晚自動從公開資訊觀測站「法人說明會一覽」抓取；`config/manual_events.json` 的手動清單保留為備援。
- A10：長榮航冬季＝開盤買、開盤賣；華航夏季＝開盤買、收盤賣（依 Ed 提供的最佳組合）。

## 事件型策略（第 2 階段，`scripts/event_signals.py`）

資料來源：`scripts/market.py` 每晚抓上市＋上櫃普通股的收盤、漲跌停、融資餘額，存進 `market_days`（一天一列）。

| 策略 | 觸發 | 進出場 |
|---|---|---|
| A08 大盤-5% | 加權指數單日 ≤ −5% | 當日收盤買進 → 第 5 個交易日收盤賣出 |
| 014 跌停群聚 | 上市＋上櫃普通股收跌停 ≥ 100 家，且不在前一事件起算 40 交易日內 | 當日收盤買進 → 持有 5 日／15 日收盤賣出 |
| 010 連續漲停開板 | 連續 ≥ 4 天收漲停後，第一天沒收漲停 | 當日收盤放空 → 下一交易日收盤回補 |
| 020 融資大減（E-Test 候選） | 二次群聚日（定義見程式註解，依策略包 V01/R04） | 下一交易日開盤等權買進 → 群聚日後第 20 個交易日收盤賣出 |

A08、014、010 是「當天收盤」進場，晚上推播來不及，靠 **盤中提醒**（`scripts/intraday.py`，13:05、13:15）：
接近門檻才推，沒事不推；同一天同一件事只推一次。最後是否成立以收盤為準，晚上會記錄並產生出場提醒。

第一次設定：

1. Supabase SQL Editor 執行 `sql/002_market_days.sql`。
2. Actions → **回補歷史行情** → Run workflow（預設 300 個交易日，約 70 分鐘；已抓過的日子自動略過）。
   020 的 120 日高點、穿越、二次群聚都要歷史，起點至少要比第一個判斷日早約 160 個交易日。
3. cron-job.org 新增兩個排程，在台北 **13:05、13:15**（週一到週五）呼叫「盤中提醒」的 workflow_dispatch，
   做法和處置股、庫藏股一樣。GitHub 自己的排程常延遲，只當備援；超過 13:27 程式會自動略過。

晚上 22:37 會再跑一次：融資餘額公布較晚，若重抓後出現新訊號（例如 020）才補推。

**主推播備援（2026-10-17 稽核建議）**：主推播 19:30 目前只有 GitHub 排程，沒有 cron-job.org 觸發；GitHub 跳過時，
21:07 的補推會把整批當「補充提醒」送出，三次都延遲就沒有推播。請在 cron-job.org 新增一個排程，台北 **19:35**（週一到週五）
呼叫「每日訊號推播」的 workflow_dispatch（inputs 都留預設）。同一天主推播已成功送出就不會重複推（`daily_push.py` 會查 push_messages）。

**跨年休市日**：訊號日期都靠 holidays 表，哪一年沒有資料那一年的日期就不算（不猜）。TWSE 公布隔年休市日後，
Actions →「更新休市日」跑一次（每週一也會自動跑），否則 1 月的出場（例如 A10 長榮航）、009 統領進場等會算不出來。

## 現增策略（`scripts/cash_issue.py`）

004 大額現增放空：每晚掃最近 7 天公開資訊觀測站重大訊息，主旨含「認股基準日／繳款期間」者讀內文，
取「每仟股認購股數」與「原股東繳款期間」。每仟股 > 50 股 → 繳款截止日開盤放空、進場日起算第 10 個交易日收盤回補。

- 公告沒寫每仟股時，以「原股東認購股數 ÷ 已發行普通股數」換算，推播會註明是換算值。
- 繳款日程延後（「原訂…待訂定後另行公告」）的公告略過；只有發行價格待訂定不算延後。
- 同一家公司後續的補充／更正公告會覆蓋前一次的日期。

017 現增上市賣壓：每晚查公開資訊觀測站公告查詢（t146sb10）的增資新股上市公告，取新股首次可交易日 D；
用 `cash_issues` 表裡原認股基準日公告的每仟股認購股數比對，≥ 146.18 → D-1 開盤放空、D 開盤回補。

第一次設定：Supabase 執行 `sql/003_cash_issues.sql`，再到 Actions → **回補現增公告** → Run workflow（預設 120 天）。

## 內部人申報轉讓（`scripts/insider.py`）

019：每晚掃最近 7 天的「內部人持股轉讓事前申報日報表」。轉讓方式只有一般交易、申報人是法人（名稱含公司／投資／基金…）、
不是變更申報；申報日加權收盤低於 20 日均線 → 下一交易日開盤放空，進場日算第 1 天、第 5 個交易日收盤回補。
同一檔還在持有中的新申報略過（只看本策略自己的持倉）。

## 大幅除權息（`scripts/exright.py`）

A11：每晚讀上市 TWT48U_ALL、上櫃 tpex_exright_prepost 預告表。在 T-6 那晚用當天收盤試算
參考價 = (P − 現金股利 + 認購價×現增配股率) ÷ (1 + 無償配股率 + 現增配股率)；幅度 ≥ 15% 且
稅拖曳 (現金股利 + 無償配股率×面額) ÷ P ≤ 5% → T-5 開盤買、T0 收盤賣。回測用 T-1 收盤，接近門檻的會標註。
